# Refactor

1. Inventory the existing document set and map each section to a Contract.
2. Identify duplicated, misplaced, stale, or contradictory content.
3. Propose moves by target document. Do not widen the write scope without user
   authority.
4. Move content without changing its factual meaning; leave a useful relative
   link at the old reading path.
5. Preserve external anchors where practical. If an anchor must change, report
   the compatibility impact.
6. Remove duplication only after the canonical destination exists.
7. Run the checklist against every changed document.
8. Report moves, redirects or links, removed duplication, and unresolved
   conflicts.

Example: keep repository identity in README, move local development commands to
DEVELOPMENT, and move compatibility and release ownership to MAINTAINER.
